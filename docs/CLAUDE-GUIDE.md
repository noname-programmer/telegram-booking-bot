# 🤖 Как работать с Claude в этом проекте

Инструкция для владельца проекта: как настроить Claude один раз и потом получать от него максимум пользы.

---

## 1. Где что настраивается

| Где | Что там | Кто меняет |
|---|---|---|
| **Репозиторий** (`CLAUDE.md`, папка `.claude/`) | Правила для Claude, команды-навыки, разрешения | Claude через PR, ты принимаешь |
| **Настройки облачной среды** (название среды вверху сессии → Edit) | Токены и другие секретные переменные | Только ты |
| **claude.ai** ([connectors](https://claude.ai/customize/connectors)) | Подключения к сервисам: Gmail, Google Drive и т.д. | Только ты |

Всё, что лежит в репозитории, работает в любой новой сессии автоматически: в браузере, в приложении на телефоне, на компьютере.

---

## 2. Разовая настройка (чек-лист)

- [ ] **Перевыпусти токен Serverless** демо-бота: @BotFather → бот → Serverless → CLI Access. Старый токен был в чате, поэтому считай его засвеченным.
- [ ] **Сохрани новый токен в переменных среды:** вверху сессии нажми на название среды → **Edit** → **Environment variables** → строка `TGCLOUD_TOKEN=новый_токен` → сохрани.
- [ ] Токены клиентов добавляй так же, с именем клиента: `TGCLOUD_TOKEN_TABASSUM=...`
- [ ] **Начни новую сессию:** переменные подхватываются только при старте.

> 🔒 **Главное правило:** токены никогда не пишутся в чат. Claude знает это из `CLAUDE.md` и сам их не попросит.

---

## 3. Команды

Пиши их в чат, как обычное сообщение.

| Команда | Что делает | Пример |
|---|---|---|
| `/new-client` | Делает бота для нового клиента: спрашивает недостающие данные, настраивает, проверяет | `/new-client стоматология Tabassum в Юнусабаде` |
| `/deploy` | Загружает бота в Telegram (демо или клиента) | `/deploy` или `/deploy tabassum` |
| `/check` | Проверяет, что ничего не сломано, и объясняет результат простыми словами | `/check` |
| `/explain` | Объясняет любой файл, функцию или изменение простыми словами | `/explain отмена записи` |
| `/code-review` | Встроенная проверка изменений на ошибки | `/code-review` |

Ещё есть **помощник-проверяющий** (`reviewer`). Попроси: «проверь мои изменения через reviewer». Он сверит изменения с правилами проекта и поищет забытые токены.

## 4. Режимы работы

Выпадающий список рядом с полем ввода:

| Режим | Когда выбирать |
|---|---|
| **Plan** | Большая или непонятная задача. Claude сначала изучает проект и показывает план, а меняет что-то только после твоего «да» |
| **Auto** | Обычная работа. Claude делает большинство действий без лишних вопросов |
| **Accept edits** | Claude свободно меняет файлы, но спрашивает перед запуском команд |

Совет: новую функцию начинай в **Plan**, читай план, задавай вопросы, потом переключайся на **Auto**.

---

## 5. Как ставить задачи

**Хорошая задача** = что сделать + для кого или зачем + как проверить.

| ❌ Плохо | ✅ Хорошо |
|---|---|
| «сделай лучше» | «Клиенты путают кнопки. Сделай кнопки времени крупнее: по 3 в ряд вместо 4» |
| «добавь оплату» | «Добавь предоплату 20% через Telegram Payments при записи на услуги дороже 200 000 сум. Сначала покажи план» |
| «не работает» | «Нажимаю „Мои записи“, бот молчит. Вот скриншот. Что сломалось?» |

Полезные приёмы:
- **Прикладывай скриншоты.** Перетащи картинку в чат, Claude её увидит.
- **Ссылайся на файл:** «посмотри `@tgcloud/lib/config.js`».
- **Проси объяснить:** «объясни, что ты поменял, как будто мне 12 лет».
- **Одна задача — одна сессия.** Для новой большой задачи начинай новую сессию, так Claude не путается в старом контексте.

---

## 6. Типичные сценарии

**Новый клиент, от начала до конца**
1. `/new-client` и описание бизнеса. Claude спросит недостающее и создаст ветку `client/<имя>`.
2. Клиент создаёт бота в @BotFather и включает Serverless. Ты сохраняешь его CLI-токен как `TGCLOUD_TOKEN_<ИМЯ>` и начинаешь новую сессию.
3. `/deploy <имя>`.
4. Клиент отправляет боту `/myid`. Ты просишь Claude добавить этот ID в админы и снова пишешь `/deploy <имя>`.

**Бот сломался**
«Бот @… не отвечает на кнопку X. Вот скриншот». Claude найдёт причину, исправит через PR, а после принятия PR ты пишешь `/deploy`.

**Новая функция**
Режим Plan → описание задачи → читаешь план → «делай» → Claude открывает PR с объяснением → проверки GitHub зелёные → ты принимаешь PR.

## 7. Что работает, а что нет

| | В облаке (браузер, приложение) | Claude Code на компьютере |
|---|---|---|
| `CLAUDE.md`, команды, разрешения из репозитория | ✅ | ✅ |
| Connectors с claude.ai | ✅ | ✅ |
| Переменные среды (токены) | ✅ задаются в настройках среды | задаются на компьютере |
| **Плагины** (`/plugin`) | ❌ не работают | ✅ |

Поэтому всё полезное лежит прямо в репозитории: так оно работает везде. Если когда-нибудь установишь Claude Code на компьютер, плагины смотри командой `/plugin`.

---

## 8. Безопасность

- Токены только в переменных среды, никогда в чате и в коде.
- Изменения попадают в `main` только через PR с зелёными проверками.
- Если Claude предлагает удалить тест, «чтобы прошло», или вписать токен в код, отвечай «нет» и спроси, зачем.
- Засветил токен? Сразу перевыпусти его в @BotFather.
